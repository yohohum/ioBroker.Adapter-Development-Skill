# Безопасность адаптера

Основные первоисточники: [Adapter security](https://github.com/ioBroker/ioBroker.docs/blob/master/docs/en/dev/adaptersecurity.md), [js-controller](https://github.com/ioBroker/ioBroker.js-controller).

## 1. Секреты конфигурации

`protectedNative` ограничивает доступ других адаптеров к отмеченным native-полям, но **не является шифрованием**.

`encryptedNative` сообщает контроллеру, что отмеченные native-поля должны храниться зашифрованными и автоматически расшифровываться для runtime адаптера. Точная поддержка и минимальные версии контроллера должны быть проверены в актуальной документации и матрице совместимости проекта.

Для паролей, API-ключей, токенов и других credentials обычно требуется рассмотреть оба свойства:

```json
{
  "protectedNative": ["password", "apiKey"],
  "encryptedNative": ["password", "apiKey"]
}
```

Это фрагмент для понимания механизма, а не готовый `io-package.json`: размести поля на корректном уровне согласно текущей схеме.

Не включай секрет в `common.native`/пример/README. Для Admin UI поле `password` только маскирует ввод; оно само по себе не шифрует значение.

## 2. Логи

Запрещено логировать:

- полный объект `native`/`config`;
- заголовки `Authorization`, cookies, bearer token;
- пароли, private key, refresh token, session id;
- URL с credentials в userinfo/query;
- полные сетевые пакеты, если в них содержатся персональные или секретные данные.

Логируй тип операции, устройство, код ошибки и безопасный контекст. Для диагностики используй redact-маску.

## 3. Транспорт и TLS

- Используй TLS-проверку по умолчанию.
- Не отключай `rejectUnauthorized` только ради обхода проблемы сертификата.
- Если self-signed сертификаты являются частью поддерживаемого устройства, предложи управляемое доверие (CA/certificate pinning) и предупреди пользователя о рисках.
- Устанавливай разумные connect/request/read timeouts.
- Не передавай пользовательские строки в shell-команды.
- Проверяй входящие данные и ограничивай размер пакетов/JSON.

## 4. Валидация

- Валидируй конфигурацию до подключения.
- Проверяй типы и диапазоны команд.
- Не доверяй данным устройства: проверяй длину, формат, границы и обязательные поля.
- Обрабатывай неожиданные типы и частичные ответы.
- Не делай `JSON.parse` без обработки ошибок на границе протокола.

## 5. Защита от утечек

- Проверь `.gitignore` и `.npmignore`/`files`.
- Не коммить `.env`, dump с реальными данными, ключи и сертификаты.
- Добавь тесты, проверяющие redact-функцию.
- Перед публикацией проверь `npm pack --dry-run` и содержимое tarball.
- Не включай local `.dev-server`, `node_modules`, тестовые credentials и debug logs в npm package.
