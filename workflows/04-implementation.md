# Этап 4. Реализация

## 1. Сначала протокол, затем ioBroker

Реализуй transport и codec в изолированных модулях. Напиши тесты на известные raw frames/responses, включая повреждённые и неполные входные данные. Только затем связывай их с Adapter.

## 2. Типизация

Для TypeScript:

- подключи `@iobroker/types` способом, указанным в README пакета (`compilerOptions.types` или import);
- включи строгий режим, насколько допускает template;
- не используй `any` для протокольных ответов; `unknown` на границе + runtime validation;
- используй точные interfaces/discriminated unions;
- обрабатывай неизвестные enum/protocol values.

## 3. Команды

В `stateChange`:

- фильтруй namespace и ID;
- игнорируй `null` и `ack=true` для командного пути;
- проверяй `ack=false`;
- валидируй тип/диапазон;
- ограничивай concurrent requests, если устройство не допускает параллельные операции;
- передавай в протокол;
- обрабатывай ACK/NACK/timeout;
- синхронизируй фактическое значение отдельным readback/event;
- не подавляй ошибки пустым `catch`.

Не отправляй команду в устройство, если adapter уже останавливается или устройство offline, если протокол/UX не определяет допустимую очередь.

## 4. Polling

- Не используй необработанный async `setInterval`.
- Предпочитай таймер, который планирует следующий опрос после завершения текущего.
- Валидируй интервал: finite, positive, разумный минимум/максимум.
- Не запускай несколько одинаковых poll requests параллельно.
- Отменяй таймер и request на stop.
- Разделяй критичный быстрый polling и тяжёлую статистику.

## 5. Ошибки и доступность

Определи категории error: auth, network, timeout, protocol, validation, device-rejected, internal. Не логируй stack/response body с секретами.

`info.connection`/`connected` и device reachability обновляй по реальной логике соединения. Не делай `connected=true` только потому, что TCP socket открыт, если протокол ещё не прошёл handshake.

## 6. Обработка внешних событий

- Защити обработчик от некорректных данных.
- Обрабатывай дубликаты/старые timestamp согласно протоколу.
- Не создавай бесконечные listeners.
- Логи должны различать временный retry и устойчивую ошибку.

## 7. Cleanup

Собери cleanup в одном понятном stop path. Удаляй timers, listeners, clients, subscriptions и abort controllers. Проверь отсутствие process hang после `stop`.

## 8. Логи

Используй уровни log уместно: debug для подробностей, info для значимых lifecycle, warn/error для реальных проблем. Не логируй каждый polling tick на info.

## Критерии завершения

- [ ] Код соответствует протокольной спецификации.
- [ ] Нет необработанных Promise rejection.
- [ ] Нет неконтролируемого overlap/retry storm.
- [ ] ACK и readback семантически корректны.
- [ ] Stop освобождает ресурсы.
- [ ] Все внешние данные валидируются.
- [ ] Логи не содержат credentials.
